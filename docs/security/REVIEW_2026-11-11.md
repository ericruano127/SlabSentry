# Security and code review: 2026-11-11

**Scope:** everything since Phase F, 7 commits (about 3,200 lines):
- mobile live camera;
- reference library admin;
- performance pass (auth and consent row reuse, caches, concurrent pipeline, vision threading);
- Fly.io staging and CI/CD;
- Zod upgrade;
- Grafana Cloud / OpenTelemetry.

**Method:** manual review of every changed file against the threats below, plus automated checks:
- the type checker;
- all test suites;
- `pnpm audit` and `pip-audit`;
- `actionlint` on workflows;
- a scan for SQL built by string interpolation;
- end-to-end telemetry export to a local OTLP receiver.

This is an internal review, **not a substitute for the third-party penetration test** in `HARDENING_CHECKLIST.md`.

## Findings (all fixed in this change)

## Checked and found sound
- **SQL injection.** Every interpolated SQL fragment is a constant: column names chosen from fixed lists, and a constant eligibility subquery. User values are always parameters.
- **Access control.**
  - Template submit needs analyst+; review and retire need admin+. Every staff permission still requires aal2 (MFA).
  - The two-person rule is enforced in both the API and a database constraint. A self-review update is rejected at the database level (tested).
  - Self-approval is limited to owners behind an explicit flag, and recorded.
- **Auth and consent row reuse** (performance pass). The role is still read from the database on every request, and consent is checked against that same fresh row. Nothing per-user is cached across requests.
- **Caches.** Only global data (legal docs, plans, library, patch notes). The library never serves a stale value, so integrity failures still stop analysis.
- **Uploads (templates).** Same MIME sniffing, size limit, decompression-bomb guard and metadata stripping as user uploads.
- **Telemetry.**
  - Query strings, long digit runs, emails and tokens are redacted.
  - Header, body and credential attributes are dropped.
  - SQL has no parameter values; Redis records the command name only.
  - Health probes aren't traced.
  - The OTLP auth header is never logged.

  Verified by an end-to-end export with zero leaks of the cert number, email, signed-URL token or bearer token.
- **Containers.** `.dockerignore` keeps `.env` files, git history and `node_modules` out of the build context. Both images run as non-root; the vision image is checked in CI.
- **CI.** Workflows have `contents: read` only. Secrets reach steps only through `env`. Fork pull requests get no secrets. Gitleaks scans the full history.
- **Dependencies.** `pnpm audit` (high) is clean after the Zod 4 upgrade (GHSA-mrhx-c7xc-m3w5). `pip-audit --strict` is clean.

## Open recommendations (not code changes)
1. **GitHub `staging` environment:** restrict deployments to the `main` branch, and optionally require a reviewer for production.
2. **Staging is public:** anyone can sign up on staging. Consider Supabase sign-up restrictions (an allowlist) or keeping staging's URL private, and never load production data into it.
3. **The two moderate npm advisories** are in Expo's CLI tooling (`glob`, `minimatch`); they're build-time only. Update Expo when a release includes the fixes.
4. **A third-party penetration test** before launch (unchanged).
