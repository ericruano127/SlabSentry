|---|---|---|

| B4 | **Era-aware verification** by grading/encapsulation date of the current holder, never the item's year. Evidence order: official grading date → official label type (e.g. PSA "Label Type") → verified cert ranges → visual inference (stated as inferred, low confidence). Era mismatch flagged only when a feature exclusive to a later generation appears on a slab whose official era ended before it; absence of newer features never flagged; other generations' features marked "not applicable". | `packages/core/src/library/era.ts`, `risk/engine.ts` |
| B5 | Reports record **category, era (basis, confidence, inferred), library version + hash**; report view shows the grading era line. Public `/api/library` exposes only names, guidance and lookup links — never markers or detection details. | `report/build.ts`, `components/ReportView.tsx`, `app/api/library` |

**Research findings that shaped the design:** PSA's public cert pages show *Label Type* (e.g. "PSA Fugitive Ink Technology", "Hologram") but no grading date was found; the PSA API spec host is not reachable from this environment. So today PSA era comes from label type (when the API returns it) or visual inference. The "Hologram" → pre-LightHouse mapping and the Fugitive Ink generation's dates are marked unconfirmed.

**Needs real data / research:** confirmed generation date ranges and label-type values per grader, official sites and data access for WATA/VGA/CBCS/AFA, category shape priors for comics/games/figures, validation before enabling copy fingerprinting outside cards.
